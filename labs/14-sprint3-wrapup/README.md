# Module 14 Lab — Sprint 3 Wrap-up & Assessment Prep

## Objectives

By the end of this lab you will have:

- Reviewed what Friday's Sprint 3 assessment will check
- Identified and closed any remaining modelling or SQL gaps
- Peer-reviewed a partner's schema and queries against the checklist below
- Confirmed your team's submission is in a clean, reviewable state

## Setup

- Everything from Modules 01-13, nothing new
- A partner, ideally not from your own team

## What Friday actually assesses

Two things: a **code submission** (your team's schema and queries) and a **peer review** of
another team's solution. Both are things your team has already produced, this week; Friday
checks they're genuinely submittable and reviewable, not that you can produce something new.

## The assessment checklist

For each item, your partner should *show* you the thing, not just tell you it's done.

### SQL Fundamentals (Modules 03-05)

- [ ] Can write a SELECT/WHERE/ORDER BY query live, on an unfamiliar business question
- [ ] Can correctly explain IS NULL vs = NULL
- [ ] Can write a LEFT JOIN and explain what it surfaces that an INNER JOIN wouldn't
- [ ] Can explain the difference between a CTE and a derived table

### Data Modelling (Modules 06-08)

- [ ] Can explain 1NF, 2NF, and 3NF, each with a concrete example, not just the definitions
- [ ] Can show a working ER diagram for the mission model, using proper cardinality notation
- [ ] Can show every table's primary key and foreign keys, live, via \d
- [ ] Can show a CHECK constraint actually rejecting bad data, with the real error message

### Beyond Relational (Modules 09-11)

- [ ] Can describe the five-step structured problem-solving sequence from Module 09
- [ ] Can correctly classify a new scenario as relational, document, key-value, or columnar
- [ ] Can explain Snowflake's separation of storage and compute, in their own words

### The Mission Model (Modules 12-13)

- [ ] Team's mission database is running, loaded, and queryable right now
- [ ] client_trades exists, with matching data to client_holdings (net trades reconcile)
- [ ] Every team member can explain at least one table they didn't personally build

## Task sheet

1. Pair up with a partner, ideally from outside your own team.
2. Work through every checklist category together, partner by partner.
3. Write down specific gaps, not vague ones ("couldn't show a CHECK constraint actually
   rejecting anything," not "constraints stuff").
4. Use remaining time to close your own gaps.

## Acceptance criteria

- Every item on the checklist has been shown, not just claimed, to a partner.
- You have a specific, written list of any gaps you personally still have.
- For each gap, you've either closed it or know exactly what you'll do before Friday.

Friday: guest speaker, Weekly Knowledge Check (MCQ), Sprint 3 Assessment, Presentation, Group
Retro.
